# Install and remove Jflow candidates

F6 currently produces development candidates, not a stable public release. Read `DISTRIBUTION-STATUS.md` in the archive. No Homebrew package is available.

## Choose and verify an archive

Use `uname -s` and `uname -m`: Linux maps to `linux`, macOS/Darwin to `darwin`; x86_64 maps to `amd64`, aarch64/arm64 to `arm64`. Obtain the corresponding `jflow_<version>_<os>_<arch>.tar.gz` and `checksums.txt` from the same trusted build. A CI artifact ZIP must first be unpacked to expose those files.

Set `archive` to the actual downloaded filename. Verify that exact archive before extracting it:

```sh
archive='jflow_<version>_darwin_arm64.tar.gz'
# macOS; with all four archives in the directory:
shasum -a 256 -c checksums.txt
# Linux equivalent:
sha256sum -c checksums.txt
```

The full manifest covers all four archives; download all four for the commands above. If you downloaded only one, compare `shasum -a 256 "$archive"` (macOS) or `sha256sum "$archive"` (Linux) with its exact filename entry in `checksums.txt`. Checksums verify content, not publisher identity.

```sh
mkdir -p jflow-extracted
tar -xzf "$archive" -C jflow-extracted
mkdir -p "$HOME/.local/bin"
install -m 755 jflow-extracted/jflow "$HOME/.local/bin/jflow"
export PATH="$HOME/.local/bin:$PATH"
jflow version --format=json
```

Add the PATH line to your shell startup file if needed. For upgrades, exit running sessions, retain the previous executable if you need rollback, verify the new archive, and repeat the install. Configurations and credentials remain separate from the binary.

macOS candidates are not Developer ID signed or notarized. Gatekeeper behavior for downloaded candidates has not been accepted on a clean machine. Follow your organization's approved software policy; do not disable Gatekeeper. Building reviewed source locally is another development option.

## Build from source

Use the version in `.go-version` and run `make build`. Only Go is needed to build the CLI. `make release-check` additionally needs Python 3 and downloads the pinned GoReleaser tool; it creates four local candidate archives under `dist/`, checks their SHA-256 hashes and contents, and smoke-tests the native binary. It never publishes a release. `GORELEASER=/path/to/goreleaser` can use an already installed matching version.

## Credentials, SSH and proxies

macOS uses the unlocked Keychain through `/usr/bin/security`. Linux needs `secret-tool` (commonly provided by `libsecret-tools`) and a working session D-Bus Secret Service. A locked/missing store reports an error; secrets are never saved to a plain-text fallback.

Start with `jflow auth login --help`, configure a named profile, then run `jflow auth status`, `jflow me`, and `jflow mine`. Scoped tokens require the real Cloud ID. See the repository's `docs/authentication.md` and `docs/workflows.md` for profile methods and confirmed transitions.

In SSH/headless sessions without a keyring, use `auth login --no-store --token-stdin` with the other required flags and a trusted secret producer connected to stdin. Subsequent commands can receive an ephemeral `JFLOW_TOKEN` environment variable or `--token-stdin` where supported. Never put a literal token in command arguments or shell history. Use `jflow mine --format plain` or `jflow ui --accessible` when a full-screen terminal is unsuitable. `jflow link KEY` prints a URL for a local browser when remote browser launching is unavailable.

The HTTP client honors `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY`. `JFLOW_CA_CERT` names a PEM certificate file for an approved corporate CA; TLS verification remains enabled. Use `jflow doctor` and `jflow config validate` to diagnose setup, and `jflow profile list/use` to select profiles.

## Shell completion and help

Completions are generated by Cobra and included under `extras/`; they do not contact Jira or install themselves. Load bash completion in your current session with `source <(jflow completion bash)` (bash-completion v2 is required). For zsh, put `extras/_jflow` in a directory on `fpath` before `autoload -Uz compinit; compinit`. For fish, copy `extras/jflow.fish` to `~/.config/fish/completions/jflow.fish`.

`jflow completion bash|zsh|fish` prints scripts. `--format=json` returns the script in a JSON v1 envelope. `extras/CLI-REFERENCE.md` contains help generated from the same command tree as the binary. Regenerate with `make release-assets`.

## Remove

Run `jflow auth logout --profile NAME` for each profile whose local stored credential should be removed before uninstalling. Logout does not revoke the Jira token; revoke it in Atlassian when appropriate. Inspect `jflow config path` and `jflow cache status` before deciding whether to retain local settings or cached content; `jflow cache clear` removes the selected profile's cache.

Remove the executable you installed and any completion files you copied. The example installation is removed with `rm "$HOME/.local/bin/jflow"`. No automatic uninstall deletes profiles, action history, or user data. See the repository's `docs/progress-scripting.md` for persistence and retention details.
