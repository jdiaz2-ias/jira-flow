# Validation F1

Date: 2026-09-07. Local team: macOS arm64. Toolchain: Go 1.27.1.

## Scope

JSON v1 profiles; Linux/macOS paths; atomic writes and inter-process locking; personal Cloud authentication with and without scopes; persistent/ephemeral credentials; `auth login/logout/status`, `profile list/use`, `me`, `doctor`, `config path/validate`.

Common tests use synthetic credentials, HTTPS `httptest` server, and injected stores. They do not contact a Jira tenant or read real credentials. The opt-in macOS test creates and deletes a random synthetic item under the `jflow` service.

## Evidence

- Real test `TestNativeKeychainRoundTrip`: passes on macOS arm64; write via stdin, read, delete, and later absence. Includes quotes, backslash, and Unicode.
- `make check`: passes (format, vet, tests, and foundation audit).
- `make test-race`: passes on macOS arm64.
- `make build` and `make build-all`: pass; four Linux/macOS × amd64/arm64 targets.
- `go mod verify`: all modules verified; `go mod tidy` does not alter go.mod/go.sum.
- `make security`: govulncheck 1.7.0 found no vulnerabilities.
- Local binary: general help and nested JSON help checked; process contract covered by tests.
- GitHub CI: remote result will be checked when the branch is published; these results are local.

## Covered cases

- HTTPS URLs, explicit cloud ID, both REST destinations and Basic authentication.
- 401, 403, 404, 429, 5xx; redirects rejected without a second request.
- Cancellation, invalid/excessive response, and sanitized identity for terminal.
- Profile/email precedence, rejected distinct identity, credential separation, and per-profile logout.
- Ephemeral environment token; stdin token; single JSON; exit codes; write failures; nested help.
- Locked keyring, oversized token before starting process, missing secret from argv, and errors.
- Private permissions, concurrent updates, cancelable locking, and invalid configuration without overwrite.

## Limits

- No real Jira tenant was configured or queried. Scope selection in the Atlassian console must be checked with the authorized tenant; `myself` does not prove permissions to query or change issues.
- Linux Secret Service is tested via injected executor and compilation; its real run requires `secret-tool` (usual package `libsecret-tools`) and a D-Bus session with unlocked Secret Service.
- macOS uses `/usr/bin/security` directly with context and timeout. The token is hex-encoded to avoid interactive mode quoting issues; it remains protected by Keychain. It is not compatible with manual plain-text entries: references are opaque and generated by this version.
- Persistence limited to 1500 bytes per token; larger tokens may be used ephemerally. `--token-stdin` accepts up to 64 KiB and a single line.
- V1 is the first persisted schema: F0 generated no configuration. Missing, previous, or future versions are rejected without modifying the file. There is no real historical format to migrate; a future migration must define its conversion and backup.
- Configuration implements the F1 access subset. UI, cache, and workflow fields from the plan example belong to later phases and are still rejected as unknown.
- F1 does not persist issue cache. Logout removes the profile and local credentials, including pending cleanup references; it does not revoke the token in Atlassian or modify the shell environment.
